# 2026.327.2013 — feat(strata)!: the deployed posture is the default — five-minute idle unload and the picture-path reserve

## Summary

The pod's defaults are now **exactly what this project deploys**, so a fresh deploy needs no overrides:

- **`STRATA_SET: vram-reserve-mib=512 idle-unload=300`** (was empty):
  - `idle-unload=300` releases the model after **five minutes without requests** and reloads it on the next one;
  - `vram-reserve-mib=512` keeps the cushion the **picture path** needs. Pictures are ON by this candy's default (`VISION: cpu`), and `check-strata-gpu-pod` records the measurement that decides the figure: with reserve `0` a picture request dies in prefill — `prefill gemm: cublasGemmEx f16: cuBLAS status 14` with 13 MiB free — and 512 MiB is what the engine's own warning asks for on that 16 GB venue. A reserve of 0 is therefore a *broken* default for a pictures-on candy, not a max-VRAM one.
  - Both are **launcher-mapped server settings** (`SERVER_CONFIG_OPTIONS`), so they never reach the engine's argv — the `unknown argument` failure the `STRATA_SET` comment above warns about does not apply.
- **A recorded non-default, so no one re-derives it:** upstream **refuses `lazy_load` whenever a vision reader is configured** — `runner.py` skips the key in the run-defaults and carried-settings paths with `# lazy loading is text-only`, although the server supports it. Measured: 16 GB resident at start with `VISION: cpu`, 3 GB with `VISION: off`. Tracked in opencharly/layer-strata#31.
