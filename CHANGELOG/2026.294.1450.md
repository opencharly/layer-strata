# 2026.294.1450 — feat(strata): pictures on by default, at a 64K context, applied on every start

## Summary

**Pictures on by default, at a 64K context, applied on every start** — and the defaults are the ones an agent client actually needs.

The bug this fixes: `VISION` was dead configuration on every installed model. The candy exposed it, the entrypoint passed it to `setup.py`'s install pass — and that install pass runs **only** when the run config is absent or `REINSTALL=1`. So on any restart, redeploy, or community pack, `VISION` reached no code that wrote anything: the config never gained a `vision` section, `/health` kept answering `"images": false`, and nothing reported the knob was ignored. The Layer-B overlay could not carry it either — `"vision"` is `SETUP_OWNED` and `charly-merge-config.py` refuses those by design.

Three defaults change, and one mechanism is added:

- **`VISION: cpu`** (pictures on, CPU reader — nothing taken from the card) and a charly-owned **vision pass** (`candy/strata/charly-vision.py`) that writes the setup-owned `vision` section on **every** start, in `setup.py`'s own shape, atomically with the engine's `.bak` convention. It fetches the encoder **once** into the model store (model data, licensed with the weights, never baked), reuses it thereafter, and settles the `lazy_load` pair upstream's settings validator refuses. When no encoder can be had it prints **one line** and the server serves text.
- **`CONTEXT: 65536`** — an agent client needs the room (one Hermes Agent turn measures ~12K prompt tokens before it acts), and it is affordable because the KV cache streams to system RAM from 64K up.
- **`STRATA_RUN_ARGS: --vram-reserve-mib 1024`** — the reserve 64K needs on a small card. The number is measured, not preferred: at 64K on a 16 GB card the engine's own 700-MiB default left a request **413 MiB** free and warned that the driver can page GPU memory to RAM (upstream #2065, asking for 832); at **960** it still measured **509 MiB — 3 MiB under the engine's own 512-MiB threshold** — and asked for **1024**, which clears it. (The request in this session was 960; it is 1024 because 960 measurably does not clear the engine's threshold — see the table under "How tested".)

Plus the tests that make the change provable: four build-context checks (encoder **software** in the image, its stamp tied to the engine, the family→encoder table equal to upstream's own, and the pass driven against a synthetic config), and `check-strata-gpu-pod` now proves pictures-on **from the DEFAULT**, including one real PNG round-trip.

`LEDGER.md` (new) is this repo's decision record — V1–V9 — written because the D-ledger this family cites throughout (`opencharly/opencharly`, `plan/strata-layer-and-pod.md`) is **absent** from that repo's `origin/main`; recorded as open item **O1** rather than reconstructed from its citations.

Closes #18

The review was right that V5 read as though this change bakes the encoder. It does not:

above as its proof.
