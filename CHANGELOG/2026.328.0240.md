# 2026.328.0240 — feat(strata)!: lazy loading WITH pictures — lift the launcher's vision guard

## Summary

Upstream's launcher **refuses `lazy_load` whenever a vision reader is configured** — `strata_cli/launch/runner.py` skips the key in BOTH settings paths with `# lazy loading is text-only` (opencharly/layer-strata#31). The **server** supports the combination — `serve/server.py`: `lazy = a.lazy or cfg.get("lazy_load") is True`, and "vision encoder unloaded; it starts with the model" — so the refusal is launcher policy, not a capability limit. This makes **lazy + pictures** the pod's behaviour:

- **launcher patch**: each guard replaced **exactly once or the build fails naming this decision** (the `P10` pattern), with a post-check that the patched lines are present;
- **entrypoint patch**: seeds `${XDG_CONFIG_HOME:-/data/config}/strata/run-defaults.json` with `{"lazy_load": true}` **when absent** — at container start, never at build, because `/data` is the runtime bind and a build-time write would be masked. An operator who already has the file keeps it.
- **coverage in this change**: the build-context check `strata-lazy-loading-patched` (`id: strata-lazy-loading-patched`) greps the patched launcher lines and the entrypoint seed, so a reverted or upstream-moved patch fails the image build. It is green in the bed run pasted below (`status: PASS`, `exit=0`), and it cannot be satisfied without the patch step it guards.
