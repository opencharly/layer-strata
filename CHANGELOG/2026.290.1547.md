# 2026.290.1547 — fix(strata): the GPU bed claims the shared axis, so a CDI pod can acquire the card

## Summary

**The GPU bed could not acquire the card.** `check-strata-gpu-pod` is a **CDI pod**, and it declared
`requires_exclusive: [nvidia-gpu]` — the **VM / sole-use axis**. Measured on host `a` (2026-10-17):

```
charly: error: command "check": acquiring resources for check-strata-gpu-pod:
  freeing nvidia-gpu for vfio passthrough: setting resource "nvidia-gpu" to vfio mode:
  switch-to-vfio REFUSED: nvidia still held by external process(es): Hyprland, nvtop
  (refusing to force-unbind — would wedge the device_lock)
BED-EXIT=1        ← died at ACQUISITION, before any image was built
```

`/charly-core:deploy` states the rule directly: *"a GPU-CDI **pod** declares `requires_shared: [nvidia-gpu]` and
the arbiter flips the whole IOMMU group **vfio→nvidia+CDI** at the first claimant's deploy and back only when the
LAST claimant releases."* One field in the bed, plus the comment above it, which named the same wrong axis.

## How tested

- `charly box validate` — the class pre-flight for a manifest change: **OK, 0 warnings, 0 errors**.
- **`check-strata-gpu-pod` — named, with the measured contrast between the two field values on the same host:**
  - **with `requires_exclusive`** (current `main`): the run above — **died at acquisition, `BED-EXIT=1`**, no image built.
  - **with `requires_shared`** (this head): the bed **acquired the card, built the full cachyos+CUDA+engine image**
    (`[image-build] PASS after 17m56s`, `strata-engine-binary` / `strata-engine-stamp` / `strata-venv` all PASS)
    and reached the container phase. It then failed **one** step — `nvidia-container-toolkit-gpgcheck-enforced`,
    the **pre-#12** probe, unrelated to this change and fixed upstream in `layer-nvidia#12`.
  - So this change is what makes the bed able to run at all; the remaining step's cause is a separate, landed fix.
