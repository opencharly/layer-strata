# 2026.290.1137 — docs(strata): the skill's Related block no longer names one ref twice

## Summary

Corrects the `strata-layer` skill's `## Related` block, which documented **one ref as two different things**:

```diff
- `/charly-strata:strata` (plugin) — `charly strata`, the host-side management CLI.
+ `charly strata` — the host-side management CLI, shipped by the out-of-tree
+   `opencharly/plugin-strata` command plugin. That plugin owns no `skill:` entity, so it has
+   no `/family:skill` ref of its own; naming it here in prose avoids colliding with the box's
+   ref above.
```

`/charly-strata:strata` is a single `<plugin>:<skill>` ref resolving to the `strata` skill of plugin `charly-strata`, which **is the box** — the sibling generated page `strata/skills/strata/SKILL.md` carries `name: strata` and describes the box. It cannot also denote the management CLI. The first bullet (the box) is correct and stays; the second is now prose, so no ref is invented or duplicated.

**Why this repo, and why now.** The defect was raised by the validator on `opencharly/marketplace#508`, which **ships this page**: the corpus there is generated from this candy's `skill:` entity, so the contradiction appears in a consumer-facing artifact of that PR. A filing alone does not discharge a finding raised on the PR — the artifact ships with it — so the source is corrected here, and `#508` re-pins to this fix's tag and regenerates in the same PR. Closes `opencharly/layer-strata#2`.
