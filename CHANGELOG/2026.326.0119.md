# 2026.326.0119 — feat(strata)!: the API key is a posture, and the launcher switches are mapped

## Summary

Makes the API key a **posture** and gives the launcher's two hardcoded switches a name, closing the
keyless half of opencharly/layer-strata#27.

`strata launch` accepts `--access` and `--no-api-key`, and its own help says `--no-api-key` shares
beyond the computer with "a warning is shown, nothing is refused" (`cmd.py:140`); `check_access` only
WARNs for `lan` without a key (`launch/settings.py:217-225`). Upstream's v0.2.16 **entrypoint**,
however, passes `--access lan` as a literal, has no variable for either switch, and appends
`--api-key-env` whenever a key exists. With `secret_require: API_KEY`, a key therefore always
existed, and the nearest knob (`STRATA_SET`) fed the ENGINE — which answered `unknown argument`,
exited, and had the value persisted into the preset, so every later start failed the same way.

The fix keeps upstream's entrypoint **verbatim** and adds exactly the two switches it hardcodes:

- **`STRATA_ACCESS`** (`lan|local`, default `lan`) replaces the `--access lan` literal.
- **`STRATA_NO_API_KEY`** (`1` = keyless) passes the launcher's own `--no-api-key`, and **only when
  no key was handed in** — a key handed in always wins, so a deployment holding a key cannot
  accidentally serve keyless.
- **`secret_require: API_KEY` → `secret_accept`**: with nothing stored, nothing is injected (the
  fact ledger `P7` already measured), which is exactly the keyless state.

Why a patch and not the RCA's "container command": measured against the pinned entrypoint, running
`strata launch` directly DROPS the whole env→flag mapping — the entrypoint ignores argv and builds
`set -- launch …` from the env — so every deployment would have to restate MODEL/CONTEXT/VISION as
flags and the candy's env defaults would become dead. A second entrypoint (a renderer) is what
ledger `P3` deleted and R2 forbids. The patch maps two flags; it re-implements no setting.

Docs and the decision record move in the same cutover: ledger `P10` states the decision and its
invalidation (delete the patch the moment upstream exposes an env); `P7` is marked superseded in
part and its duplicated Control/Invalidated pair is deleted; `AGENTS.md`, `README.md` and the layer
skill describe the three legal postures.

## Change classification

**Breaking change + rollback:** the declared contract changes for consumers — `API_KEY` moves from
`secret_require` (charly mints) to `secret_accept` (nothing is injected unless stored). A consumer
that relied on the minted value must either store one (`charly secrets set charly/secret/API_KEY`) or
accept upstream's key in the volume; a keyless consumer sets `STRATA_NO_API_KEY: "1"`. Rollback is a
revert of this squash commit plus one `charly config` on each deployment, which then mints a key
again.
