# 2026.323.1751 — feat(strata)!: install Strata v0.2.16's released artifacts and run upstream's entrypoint

## Summary

Takes `layer-strata` to Strata **v0.2.16**, which is not a version bump: upstream deleted the whole
tree this layer baked against (`Dockerfile`, `setup.py`, `CMakeLists.txt`, `src/`, `serve/`,
`requirements.txt`) and now PUBLISHES the compiled artifacts. So the layer stops compiling and
installs them, runs them through upstream's own container entrypoint, and composes the POD (CDI)
GPU contract instead of the VM one.

Head: `3672abdf3cd2fae26a454990f3a7993239a1fdd5` · 14 files changed, 1562 insertions(+), 2235 deletions(-)

**The layer.** `candy/strata/charly.yml` now:

- downloads the release's own two archives — the Terminal (`strata-control-0.1.62-linux-x86_64.tar.gz`,
  94 MB) and the signed CUDA-13 engine COMPONENT
  (`strata-engine-0.1.62-linux-x86_64-cuda-cuda13.tar.gz`, 580 MB) — from the pinned `v0.2.16`
  release, `sha256`-gates both before anything is unpacked, and unpacks them into
  `/opt/strata/terminal` and `/opt/strata/components/engine/<component>/`, the layout upstream's
  own `tools/docker/Dockerfile` builds;
- installs upstream's `tools/docker/entrypoint.sh`, `healthcheck.sh` and `strata-wrapper.sh` from
  that pinned tag — pinned by CONTENT as well, since these are the files the running service
  executes — and supervises `/opt/strata/entrypoint.sh run` with `stop_timeout: 120` (upstream asks
  for two minutes: a stop drains, unloads the model and frees the page-locked RAM);
- requires `layer-cdi` (the POD GPU contract, which requires `layer-cuda` itself) and
  `layer-supervisord`, and DROPS `layer-nvidia` and `layer-build-toolchain`. Nothing is compiled, so
  no `nvcc`, no CUDA toolkit, and no driver user-space in the image: the component bundles
  `libcudart`/`libcublas`, and the driver arrives from the host through CDI;
- keeps `VISION: cpu` (pictures ON by the family's default) and `CONTEXT: 65536`, drops
  `STRATA_RUN_ARGS`, `STRATA_OVERLAY_JSON`, `LOW_RAM`, `STRATA_MEMORY_LIMIT_MIB`, `REINSTALL`,
  `KV_STREAMING`, `RESIDENT_BUDGET_GIB`, `LAYER_SPLIT`, `HOST` and `GGUF_DIR` from its surface, and
  declares `API_KEY` as the secret.

**The image.** `box/strata/charly.yml` is the final composition (ledger D-2): `base:
pod-cdi.pod-cdi`, through an `import:` of `opencharly/pod-cdi` at a merged tag, with exactly one
candy on top. The old base was the CachyOS distro box plus the VM-contract GPU stack, on an image
that is deployed as a pod — which is the contract violation this change removes.

**The bed.** `check-strata-gpu-pod` is adapted to the new surface: `MODEL_PATH` names the staged
shards inside `/data/Strata-data/models/`, `CONTEXT` is the literal it asserts, and its own
assertions are on HTTP/CLI behaviour instead of the old runtime's internal file names.

**Deleted in this change** (R5): `charly-build-engine.py`, `charly-entrypoint.sh`,
`charly-vision.py`, `charly-merge-config.py`, `charly-merge-args.py`.

The POD extraction (`box/strata` + the bed + the box skill moving to `opencharly/pod-strata`, the
umbrella import key, the marketplace refs) is the rest of the cutover tracked by

**The atomicity anchor: at this PR's head, `box/strata/charly.yml`, `check-strata-gpu-pod` and
`.agents/skills/strata/SKILL.md` all still exist HERE, fully working on the new contract — the box
builds, the bed runs, the skill describes what ships.** They are ADDED to
`opencharly/pod-strata` (that repo's PR-1, which pins this candy at the tag this PR mints) BEFORE
they are deleted from here (`layer-strata` PR-2, which follows `pod-strata`'s merge). So there is no
window in which that content is in no repo: it moves home first and is deleted second, and this PR
neither removes nor relocates it. Nothing in this PR's own scope is deferred — the five scripts it
deletes have no successor, because upstream's entrypoint is the replacement and it is installed in
the same commit.

`UserNS=host` + `User=0:0` is `opencharly/plugin-deploy-pod#82`'s fix, not a choice made here, and it is
**not** a rootless regression: the failing syscall was the kernel's idmapped-mount path

owns the filesystem's superblock — a rootless container can never idmap HOST files. Under `userns=host`
podman requests no idmap, and container uid 0 IS the invoking host user. Measured on this image:
`--userns=host --user 0 --cap-drop ALL --security-opt no-new-privileges --device nvidia.com/gpu=all` runs
supervisord → `strata` → `Engine 0.1.62 (cuda) is installed` → `usable: true, signed: true`, the bind
writable, host files `1000:1000`, and `podman info` still reports `rootless=true`.

`PodmanArgs=--security-opt no-new-privileges` comes from the box's new `security: security_opt:`, which
makes an already-true zero-escalation posture enforced rather than incidental. (`cap_drop` is not

## Change classification

**Change class:** runtime — the image's composition and its layer contract change, so the class gate is
the family's `disposable: true` bed, `check-strata-gpu-pod`.

**Breaking change + rollback:** breaking for four consumers.

1. **Every existing deployment's `env:`.** `STRATA_RUN_ARGS`, `STRATA_OVERLAY_JSON`,
   `STRATA_API_KEY`, `GGUF_DIR`, `LOW_RAM`, `REINSTALL`, `KV_STREAMING`, `RESIDENT_BUDGET_GIB`,
   `LAYER_SPLIT` and `HOST` are no longer read by anything in this image. `STRATA_RUN_ARGS` was where
   an existing deployment carried its context (`--max-context`), so such a deployment must move to
   `CONTEXT` + `STRATA_SET` and re-save its preset; `STRATA_API_KEY` becomes `API_KEY`;
   `STRATA_OVERLAY_JSON`/`STRATA_RUN_ARGS` become `strata profile` / `STRATA_SET`.
2. **`API_KEY` is now `secret_require`, so `charly config` has to run once.** The layer previously
   declared the key as an `secret_accept`, and an accepted name with no stored value injects nothing
   at all (measured) — a keyless posture that cannot exist, since upstream always serves with a key.
   It is required now, which means `charly config` MINTS `charly/secret/API_KEY` and writes
   `Secret=…,type=env,target=API_KEY` into the unit: **a deployment of this image is not instantiable
   until that has happened**, and a deployment configured some other way must supply `API_KEY`
   itself.
3. **The first start MOVES the model store, one way.** Upstream's entrypoint renames
   `/data/models`, `/data/packs` and `/data/mtp` into `/data/Strata-data/` (rename-only, idempotent,
   and it skips anything that is its own mount). **Rollback to a v0.1.x image therefore needs the
   reverse move**: `mv /data/Strata-data/{models,packs,mtp} /data/` before starting the old image,
   which reads `/data/models`. `/data/vision` is not moved, so a pictures-on first start re-fetches
   the encoder (~0.9 GB).
4. **The image's base contract** moves from the VM GPU stack to the POD/CDI one. An image built from
   this repo needs a host whose runtime injects the driver (CDI spec + `--device
   nvidia.com/gpu=all`); it no longer carries a driver user-space of its own.

Rollback procedure: `charly update strata -i <instance> --tag <the previous CalVer>` (or redeploy the
previous image), then perform the reverse store move in (3) if the store was already migrated.
