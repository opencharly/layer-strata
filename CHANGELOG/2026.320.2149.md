# 2026.320.2149 — fix(requires): advance the GPU stack pins past the driver-shadowing fix

## Summary

`layer-nvidia` v2026.314.0708 → **v2026.320.1938** and `layer-cuda` v2026.314.0705 →
**v2026.320.2103**, producer-first — both tags existed before this pin moved, and both carry
the CDI driver-shadowing fix (opencharly/layer-nvidia#22, opencharly/layer-cuda#19).

**Why this is a real defect, not housekeeping.** An image that bakes `nvidia-utils`' driver
user-space shadows the host's injected NVML: NVIDIA's CDI `create-symlinks` hook points each
SONAME at the newest versioned copy present INSIDE the container, so the image's copy wins and
`nvidia-smi` dies with `Driver/library version mismatch` on any host whose kernel driver is
older than the distro package. Measured on a CachyOS GPU image before the fix:

```
$ nvidia-smi -L
Failed to initialize NVML: Driver/library version mismatch
NVML library version: 620.70          (host CDI mount carried libnvidia-ml.so.615.78.08)
```

Every strata image built from this candy carried the same two pre-fix pins and therefore the
same exposure. The comment at the require site records it, so a future re-pin below the fix
meets the reason.

**What this does NOT do — corrected on the thread.** An earlier revision of this body claimed
that advancing these requires made `opencharly/distro-cachyos` validate clean. That was wrong:
I re-measured with these requires already advanced in a local tree and the conflict persisted.
The claim is withdrawn; opencharly/distro-cachyos#184 carries the corrected RCA and every
measurement. This PR stands on its own defect.
